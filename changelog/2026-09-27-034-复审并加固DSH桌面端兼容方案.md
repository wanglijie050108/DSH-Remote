## 对 033 的纠正

033 的“无需破坏性重构”结论保留，但解决方案不完整，遗漏了以下会阻塞交付或造成安全问题的事实：

1. 二维码 300 秒 TTL 到期后，插件没有 timer 注册下一代 token；
2. Web 与 Desktop 双实例冲突不能只靠使用说明，必须在 Bridge 连接前做本机单活保护；
3. 当前 macOS 实测 `$DSH_HOME/mobile-link` 为 `0755`、`identity.json` 为 `0644`，身份私钥权限过宽；
4. 插件没有 DSH/Node 版本声明、客户端 bundle 和发布产物门禁；
5. 客户端插件也会被手机页面加载，二维码 UI 必须同时做 Desktop 主页面检测和 Host authority 限制；
6. 033 没有写出失败恢复、更新重启语义和可判定的验收门禁。

本记录不修改已发布的 033；新增 08 方案作为后续实现真源。

## 定案方案

- **协议不动**：固定 authority、帧格式、Bridge、TURN、WebRTC 和 App 网络层全部复用；
- **UI**：插件通过 `dsh.client` 向 `plugins.detail.section` 贡献 Desktop-only 区块；
- **状态通道**：复用 `ctx.connection.fetch.register()` 注册已认证、no-store 的 status/QR GET，不新增 Electron IPC 或 Typert；
- **秘密最小化**：status 不含秘密，QR 仅以内存 PNG 返回，不落盘、不写 URI、不进入 localStorage/遥测；
- **QR 生命周期**：300 秒服务端 TTL，285 秒可见窗口，先清旧代再注册下一代，所有异步结果带 generation；
- **单活**：每个 `DSH_HOME` 使用原子目录租约；冲突方保持插件可见但不连接 Bridge，不让 DSH 启动失败；
- **启动顺序**：安全检查目录并取得租约后才允许读取/生成 identity，封住首次双进程生成两套私钥的竞态；
- **HMR**：租约和 `boot_id` 同为进程级；热重载复用，disabled 延迟释放，nonce 防旧 disposer 误删新锁；
- **配置/安装**：先停用 Web、写 home `.env`，再从 Desktop Plugins 页安装但保持关闭，检查后启用；
- **版本**：精确声明已验证的 DSH peer，禁止用兼容豁免代替测试；
- **验收**：新增 D0–D8；全部通过且 relay-only 真机稳定 30 分钟后，才能宣称 Desktop 支持完成。
