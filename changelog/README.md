# changelog — 方案与代码改动记录

为 dsh-mobile-link 三件套（DSH 插件 / Bridge 服务端 / Android App）的所有**方案文档与代码改动**提供可回溯的轨迹。

## 三条原则

1. **一改一记**：每次改动（哪怕只改一个字）立即新建一条记录，改动与记录属同一件事，不允许"改了回头再补"。
2. **只追加不修改**：已写下的记录永不编辑、永不删除。写错了就补一条新记录，标题注明"修正 00N"，并说明错在哪。
3. **每条改动带依据**：记"为什么"时必须给出出处——用户批复、评审编号（A1/B2/M-7…）、契约 §、docs/0N §、或源码符号。照搬 SKILL.md §7 的规则：**没有出处的数字是缺陷**。

## 何时必须记录

1. 修改 `new_docs/` 下任何方案文档；
2. 修改将来各实现仓库（`dsh-mobile-link` / `remotedsh-bridge` / `remotedsh-android` / `remotedsh-contract`）的代码；
3. 契约版本升级（契约 §7 变更日志之外，在此补一条**工作区视角**的记录：含配套实施文档的同步情况与验证方式，不重复 §7 的规范级描述）；
4. 重大评审结论或用户决策，即使当时未改任何文件——它们是后续改动的依据，需留档可查。

## 文件命名与编号

- 格式：`YYYY-MM-DD-NNN-主题.md`
- `NNN` 为**全局递增**三位序号，跨日期累计、不按日重置（001、002、003…）；
- 同一天多次改动各占一个编号，不合并。

## 记录模板

```markdown
# YYYY-MM-DD-NNN · 主题

| 项 | 内容 |
|---|---|
| 类型 | 方案 / 代码 / 方案+代码 / 决策留档 |
| 触发来源 | 用户批复 / 评审编号 / 缺陷发现 / 源码核实 |
| 影响版本 | 契约 v?.?.?；01/02/03 v?.?；代码 commit/分支 |
| 变更文件 | 相对路径（处数） |

## 改了什么
逐文件逐处：位置 + 旧表述 → 新表述（摘要级，不贴全文 diff；代码改动给关键片段）

## 为什么 / 依据
决策内容与出处、论证、引用（契约 §、docs/0N §、源码符号）

## 验证
怎么确认改对了：grep 断言 / 校验脚本 / 测试用例及结果

## 回溯线索
关联记录编号（前置/后续/被修正者）、被取代的表述、上下游文档版本
```

## INDEX.md 维护

每新增一条记录，**同时**在 `INDEX.md` 表格顶部加一行（新记录在上）。INDEX 只有一行摘要，细节永远在记录文件里。

## 与契约 §7 变更日志的分工

- 契约 §7：只记**契约自身**的版本演进（规范级、三方会签视角）；
- 本目录：记**工作区全景**——实施文档同步、代码改动、验证手段、回溯线索；
- 两者互补不重复。契约升级时：§7 照常记，本目录再记一条含"配套同步情况"的记录。
