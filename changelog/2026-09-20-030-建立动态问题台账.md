# 2026-09-20-030 · 建立动态问题台账

| 项 | 内容 |
|---|---|
| 类型 | 用户决策 + 工具规则 |
| 触发来源 | 用户要求单独记录现存问题，未解决项在前、已解决项在后，并为每项标明引入原因 |
| 影响版本 | 契约 v1.0.5（无契约变更） |

## 改了什么

- 新增 `changelog/ISSUES.md`，录入本轮代码与 changelog 一致性审查发现的 25 个未关闭问题和 6 个已解决问题。
- 问题使用稳定 ID，按未解决/验证中在前、已解决在后的顺序维护；每项记录引入原因、证据和关闭条件。
- Skill §8 增加动态问题台账规则，并明确它是编号 changelog 只追加规则的唯一例外。

## 为什么 / 依据

编号 changelog 适合保存历史事实，但不能直接表达当前问题是否仍然存在。本轮审查发现 018、022、023、028 的部分“已修复”描述与当前仓库代码不一致，因此需要独立、可变且有关闭门槛的问题台账。

## 验证

- `ISSUES.md` 中未解决项位于已解决项之前。
- 每一行均有稳定 ID 和“引入原因”。
- Skill 明确了发现、状态变化、关闭和历史冲突时的维护规则。

## 回溯线索

- 前置：018、020、022、023、028、029。
- 后续修复必须同时更新 `ISSUES.md`；已解决项不得删除。
