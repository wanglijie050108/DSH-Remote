## 评审结论

**支持“Desktop 单独作为宿主”不需要破坏性重构。**

Desktop 是共享 Web 应用外的 Electron 薄壳：

- `apps/desktop-host/src/index.ts` 仍以 `runProfile({ profile: 'desktop' })` 启动 Host，并提供 `webServer`、`connection` 与完整 Web bundle；
- `apps/desktop/src/project-manager.ts:createPluginProfile` 直接复用 `PROFILE_TEMPLATES.web.bundles`；
- Desktop 默认端口虽改为 `19387`，插件已从 `ctx.webServer.port` 动态取得转发目标，不依赖 `3080`；
- `frontend-static` 在 Desktop profile 中仍提供经 `connection.authorizeIndex` 鉴权的根页面，因此手机侧固定 authority `127.0.0.1:13080`、L4 隧道、Bridge 和 App 协议均无需变化。

## 新增缺口

1. **ISS-026：Desktop 首次配对入口不可见。** `dsh-mobile-link` 只有 Host 端，二维码仅输出到 stdout；GUI 用户没有可操作入口。应增加插件页面或等价受控 UI，不应改隧道协议。
2. **ISS-027：Web CLI 与 Desktop 双实例冲突。** 两个 profile 共享同一身份文件，Bridge 会踢掉旧连接；不同进程的 `boot_id` 又会销毁既有配对。默认应先明确单活，而不是直接设计多实例协议。
3. **ISS-028：安装和自救仍写死 Web profile。** DSH 0.1.7 禁止 CLI 管理保留的 `desktop` profile；Desktop 必须通过内置插件页管理，失败恢复也应使用 Desktop 原生恢复路径。
4. **ISS-022 补充证据。** 事实校验器只识别已安装 npm 布局，无法校验 monorepo；F6 对 `authenticatedUrl()` 的旧描述也已漂移。插件传入干净根 URL，因此当前行为未受影响。

## 风险边界

- 若目标只是“让手机连接 Desktop 当前工作区”，改动集中在插件 UI、安装说明和 Desktop 实机/E2E 验证。
- 只有在明确要求 Web CLI 与 Desktop 同时保持各自配对、并让手机切换多个本机实例时，才需要重新设计实例身份和目标选择；这不是 Desktop 单端适配的前置条件。
- Desktop 使用 Electron RunAsNode 和独立 `profiles/desktop` 依赖树，仍需做一次打包产物上的插件安装、激活、重启、扫码和四项业务功能验收。
