## 决策与依据

| 项 | 决定 |
|---|---|
| 定位 | **验证平台（harness）非产品移植**；验证通过可作 v2 种子，v1 不承诺 |
| WebRTC 承载 | ArkWeb 页面标准 `RTCPeerConnection`（官方 FAQ faqs-arkweb-64：WebView 支持 WebRTC P2P；内核 Chromium → libwebrtc，与 org.webrtc 同源，G1 结论可强迁移） |
| 契约层 | ArkTS port + G2 共享向量逐字节断言；cryptoFramework 原生 ECDSA P-256/SHA-256（hello 签名）+ HMAC-SHA1（TURN 凭证）；输出若非 DER 补 BER 编码器 |
| E4 | 鸿蒙默认允许 HTTP 明文（官方 FAQ faqs-network-16），Android 原版 E4 不受影响、留待安卓设备 |
| 阶段 | H0 环境 → H1 G1-H 门禁（三类候选/pin/16KiB）→ H2 信令契约（并行）→ H3 隧道代理 → H4 G3-H 四功能 → H5 留档，合计 ≈6–10 天 |
| 失败分支 | R1-B1 flutter_webrtc-ohos（同为 libwebrtc）；R1-B2 鸿蒙降级为信令+网络+隧道层验证，G1 留待安卓设备 |
