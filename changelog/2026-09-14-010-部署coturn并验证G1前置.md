## 做了什么
1. **服务器**（Ubuntu 24.04，2C2G，root 经 ed25519 密钥登录——密钥对本 `.keys/`，已 gitignore）：
   - `apt install coturn`（4.6.1；国内环境弃 Docker Hub 路线，G1 阶段原生装，Signal 上线时迁 compose）；
   - 生成 64 位随机 `TURN_SECRET`（服务器 `/root/.turn_secret` 600 + 本地 `.keys/TURN_SECRET_114.txt`，均不入库）；
   - `/etc/turnserver.conf` 按 02 §4：`use-auth-secret + lt-cred-mech + static-auth-secret + realm + 49160-49999 relay 段 + max-bps=250000 + bps-capacity=350000 + external-ip=114.55.114.12/172.23.140.7 + no-tls + no-cli`；
2. **用户侧安全组**：3478/UDP+TCP、49160-49999/UDP 放行（控制台端口范围须英文短横线）；
3. **验证**（三层独立客户端，全部从本机对公网 IP）：
   - 原始探针（verify-turn.mjs）：STUN 绑定 PASS（自见出口 113.200.174.94）+ 401 挑战 PASS；
   - **pion/turn v4（Go 独立实现）**：ALLOCATE PASS → relay 114.55.114.12:49972；
   - **werift（项目真实 ICE 栈，verify-turn-werift.mjs）**：**host=4 / srflx=4 / relay=1 三类候选一次收齐** —— G1 判据②服务器侧达成；§5 的 `transport=tcp` 兜底端口 TCP 3478 实测可达。

- 02 §4 配置逐项落实；实测修正两处：`log-file` 须为文件路径（02 §4 预警过的版本差异实锤）；不加手写的 `listening-ip/relay-ip`；
- 05 §0.1：开发期信令仍 ws://，本次未动 Signal/Caddy（W11 联调前不部署）。

## 排障实录（教训已写入 DEPLOY.md §8）
1. 假象一：安全组未放行 → TCP 探测不可达（用户加规则后消失）；
2. 假象二：手写探针第二跳 420「未知属性 0x12」——探针自身签名细节问题；**pion 与 werift 两个独立实现均通过，以真实客户端为准**；
3. 假象三：pion/werift 突然全部超时——**是排障时自己 `pkill turnserver` 把服务停了**。教训：凡"所有客户端同时超时"，第一步 `ss -lnup | grep 3478` 确认真有监听；
4. coturn 自带 `turnutils_uclient` 对本机也报 "unknown allocate response"——工具怪癖，不作准。
