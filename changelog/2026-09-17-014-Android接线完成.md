## 复核发现并修复的 Bug

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| 1 | `AppViewModel.kt` | `persistedFp` 被 `pair.ok.agentId` 覆盖 — agentId 是公钥哈希，fp 是证书哈希（SKILL §3.1 安全锚点），不能混用 | 新增 `qrFp` 字段存 QR 中的 fp，与 agentId 分离 |
| 2 | `AppViewModel.kt` | WINDOW 帧通过 `tunnelSender.sendFrame()` 发到 data 通道 — 应发 ctl 通道 | RtcEngine 新增 `sendCtlFrame()`；WINDOW/RST/PING/PONG 统一走 ctl |
| 3 | `AppViewModel.kt` | `onNavigate` 从 WebRTC 内部线程调用 `webView.loadUrl()` — 必须在主线程 | 加 `handler.post` 包装 |
| 4 | `AppViewModel.kt` | 重连路径也调 bind(ptok) — ptok 用后即弃，重连应走已有 pair | hello.ok 中检查 `e.pair` 非空则跳过 bind |
| 5 | `AppViewModel.kt` | PAIR_REPLACED 错误 isPassive 硬编码 false — 被静默忽略 | 按 code 判断 isPassive |
| 6 | `AppViewModel.kt` | 未自动回复 PING — DSH 每 2s 发 PING，不回 PONG 60s 断连 | 收到 PING 时用 `sendCtlFrame` 回 PONG |

## 模块间数据流

```
Scan QR ⟶ PairQRCodec.parse ⟶ connect(sigURL, fp)
  └─ SignalClient.connect() ⟶ hello
      └─ hello.ok ⟶ bind(ptok) [首次] 或 跳过bind [重连]
          └─ pair.ok ⟶ turnBlock + pairId
              └─ punch.offer ⟶ RtcEngine.handleOffer ⟶ createAnswer
                  └─ pollAnswerReady ⟶ send punch.answer
                      └─ onDataChannel ⟶ onConnected
                          └─ proxy.senderProvider = rtc.tunnelSender
                              └─ WebView.loadUrl(http://127.0.0.1:13080)
                                  └─ proxy.accept() ⟶ OPEN ⟶ DATA ⇄ WebRTC ⇄ plugin ⇄ DSH
```
