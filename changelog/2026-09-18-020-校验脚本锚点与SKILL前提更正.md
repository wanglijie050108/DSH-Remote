## 为什么 / 依据

**F9/F10 的真相（逐行直读 `dsh-client-connection/lib/client.js`，DSH 0.1.5-rc.2）**

| 断言的语义 | 源码位置 | 现值 |
|---|---|---|
| 背压基数 / 倍数 / 上限 | 802–804 行 | `backoffBaseMs: …default(500)`、`backoffFactor: …default(2)`、`backoffMaxMs: …default(1e4)` —— 与旧值**完全相同**，只是从常量内联进了 Schema |
| `disconnected` 触发点 | 929 行（`!networkAvailable` 分支）、898 行（`setNetworkAvailable`） | **只在浏览器 offline 时发出**；没有"重试耗尽"分支 |
| 是否有次数上限 | 923–1012 行 `loop()` | `while (this.running)`，每代结束 `retry = true`；全文件 `grep -i maxAttempt` **零命中** → 永不放弃 |
| online/offline 监听 | 6293–6297 行 `watchBrowserNetwork` | 只挂 `addEventListener("online"/"offline")` → 只反映系统网络，不感知隧道死亡 |

⇒ **FAIL 的原因是校验脚本的写法锚点过期，不是 DSH 事实变动。** 这正是 SKILL §0 第 3 条要防的两件事之一（"DSH 会升级"），
但另一件（"本文件只是索引，verifier 才是权威"）反过来要求：**verifier 自身的锚点也必须随源码写法维护**，否则它会持续误报，
而误报的代价是下一次真的 FAIL 被当成噪声忽略。故本条按 changelog 012 的先例修正脚本而非改事实。

**§3 路径**：`Test-Path 'D:\npm-global'` → **False**；`%APPDATA%\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-client-connection\lib\client.js` → True。
脚本 `candidateRoots()` 的候选顺序里 APPDATA 在 `D:/npm-global` 之前，所以脚本一直是对的，**错的是 SKILL.md 的散文描述**——
但它会误导人去错误的路径下核对源码。

**第 9 行 → `docs/03` §4 的连带影响（重要，本次只报告不修改）**

`docs/03` §4 把 `webView.reload()` 列为**必需路径**，理由是「DSH 前端在 12.75–25.5 s 后放弃，而 ICE `failed` 可能 ~30 s」。
该理由的算术（0.25+0.5+1+2+4+5 = 12.75，0.5+1+2+4+8+10 = 25.5）只是"背压爬到 10 s 档的累计时间"，而**放弃**这一步在当前版本不存在。
因此：reload **仍可保留**（无副作用，且能顺带重跑 401 token 交换），但它的"必需性"不再有依据，需实测定论（见 new_docs/07 §B1-T5b）。
